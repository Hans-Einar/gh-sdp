## Finding and correction of earlier review

**High, resolved:** the old `gh-sdp_linux_amd64` asset would not be selected by
GitHub CLI's remote binary extension installer. REV-SPS-004-001 approved
preparation without checking that distribution boundary. Its local symlink
integration proved invocation and delegation but did not prove remote asset
selection. This review supersedes that earlier distribution-name conclusion;
the earlier recorded test executions and hashes remain historical facts.

Independently checked the official source for the installed GitHub CLI v2.97.0:
[extension manager](https://github.com/cli/cli/blob/v2.97.0/pkg/cmd/extension/manager.go).
Both binary-extension detection and binary asset selection use the platform
suffix. Linux amd64 has suffix `linux-amd64`; the new filename matches and the
old one does not. The remote installation path downloads the selected asset as
the extension executable. This differs from the local symlink path.

All executable, inspection, manifest, checksum and final-link references in
`scripts/package.sh` now use the corrected filename. The new
`TestPackagedAssetDiscovery` inspects an actual package directory, requires one
matching executable and verifies its manifest and checksum. The test has an
explicit package-directory input; ordinary tests do not silently claim this
additional package evidence.

No unresolved findings remain for this bounded correction.
