## Findings

### Medium R1 — Local special-file input blocks bootstrap indefinitely

Location: canonical SDPTool/bootstrap/bootstrap.go, lines 125–139 at the pinned
commit. The local reader calls os.Open before checking whether the object is a
regular file. A FIFO therefore blocks in open, before the regular-file guard,
without a context or local-read timeout. Descriptor, signature, key and cache
reads share this helper. The client cannot fail closed with its documented
bootstrap error status for this unsupported input.

Reproduced using the actual reviewed gh-sdp executable: create a FIFO with
os.mkfifo, set SDP_RELEASE to that FIFO, select a fresh private SDP_CACHE_DIR and
SDP_OFFLINE=false, then invoke --version. A subprocess timeout at two seconds
killed the still-blocked client; stdout and stderr remained empty. No signed
descriptor or engine execution is needed. Ordinary supported files still work.

The canonical contract requires bounded input handling and rejection of
unsupported filesystem objects. Reject nonregular paths before opening, retain
post-open validation, and add a regression proving prompt rejection. Correct the
canonical package and repin gh-sdp; do not duplicate the reader in the client.

### Medium R2 — Verification attributes unexecuted tests to the upstream pin

Location: SDP/Verification/VER-SPS-003.md, lines 50–52 in candidate 02e3db2.
The record attributes download-bounds, immutable-cache and timeout unit evidence
to the pinned upstream bootstrap package. Its bootstrap_test.go contains only
TestSignedCacheOfflineAndCorruption and TestTrustAndProtocolFailures; inspection
and rerun do not establish those specific claims. The actual client integration
adds protocol rejection and cached binary corruption evidence, not those cases.

Narrow the claim to executed evidence or add and execute the claimed tests.
Repository truthfulness and SPS-003's inspected-evidence acceptance require this
correction before closure.

### Low R3 — Design gives contradictory bootstrap exit status

Location: SDP/06--Design/design.md, lines 10–12 in candidate 02e3db2.
The first sentence assigns local configuration/bootstrap errors exit 2, while
the next assigns bootstrap errors exit 4. main.go and tests correctly implement
configuration=2 and bootstrap/start=4. Remove bootstrap from the first category.
